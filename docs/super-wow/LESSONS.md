# CONFIRMED LESSONS

1. Не читати багато великих файлів в одному контексті.

Причина:

GitHub MCP може дуже швидко заповнити контекст.

2. Одна сесія дорівнює одній конкретній задачі.

3. Максимум два великі production-файли за одну аудиторську сесію.

4. При 60–70% контексту завершувати поточну фазу та створювати нову сесію.

5. Розділяти:

FACT

HYPOTHESIS

6. Не записувати припущення як підтверджені факти.

7. Не говорити «все працює» без runtime-перевірки.

8. Не вважати самооцінку моделі достатньою перевіркою.

9. Усі production-зміни робити тільки в окремих гілках.

10. Не merge і не deploy без перевірки власником.
