# AUDIT: PRODUCTS & STATE

Прочитані файли:
js/products.js
js/state.js

Підтверджені факти:
- js/products.js є основним движком рендерингу: він відповідає за генерацію HTML карток товарів, секцій головної сторінки (Popular, New, Brands, Recently Viewed) та складних UI-компонентів (Hero Demo, Scroll Nudge).
- js/state.js є єдиним джерелом істини (Single Source of Truth): тут зберігається весь стан додатка (persistent через localStorage: gender, favs, cart, recent; та transient: tabs, filters, match pool).
- функція getCatalog() є критичною точкою збірки: вона обробляє фільтрацію за статтю, ціною, пошуком та сезонність.
- Логіка визначення статі (Gender Inference): у getCatalog() реалізовано динамічне визначення статі для «змішаних» товарів на основі діапазонів розмірів (до 40 — жіночі, від 43 — чоловічі).
- Сеансова стабільність: використовується "Seeded Shuffle" для того, щоб порядок товарів не змінювався при перемиканні між вкладками протягом однієї сесії.
- Пошук товарів: функція findProd(id) використовується як центральний метод отримання об'єкта товару з масиву S.catalog.all.

Технічні особливості:
- Секція "New" не відображається, якщо в даних немає товарів із прапором isNew.
- "Quick Add to Cart" працює лише для товарів з одним розміром (ONE SIZE).
- Реалізовано систему відстеження UTM-параметрів через localStorage.

HYPOTHESIS:
- Використання findProd (лінійний пошук $O(N)$) може стати помітним при значному збільшенні каталогу, хоча для поточного масштабу це не проблема.
- Сезонний фільтр в getCatalog() може бути занадто грубим через залежність від ключових слів у назві товару (хутро, термо тощо).
- Динамічне визначення статі для змішаних розмірів може призводити до помилок для брендів, що випускають унісекс-розміри у діапазоні 41–42.
