# AUDIT 02 — PRODUCTS AND STATE

## Прочитані production-файли

js/products.js
js/state.js

## FACT

**роль js/products.js:**
Основний движок рендерингу товарів. Відповідає за:
- Генерацію HTML-карток товарів (`prodCardHtml`).
- Використання бейджів (напр. NEW) та обробку цінових знижок.
- Відображення розділів головної сторінки (Daily Deals, Popular, New, Brands, Recently Viewed).
- Логіку "швидкого додавання" в кошик з гріда (`quickGridSize`).
- Обробку стану "останнього розміру" (`_scarcityText`).
- Реалізацію детерміністичного перемішування товарів у межах сесії (`shuffleSeeded`).

**роль js/state.js:**
Єдине джерело істини (S). Зберігає:
- Поточний стан каталогу (`catalog`).
- Дані кошика (`cart`).
- Історію нещодавніх переглядів (`recent`).
- Список улюбленців (`favs`).
- Налаштування користувача (стать, `gender`).
- Стан інтерфейсу (активні вкладки `tabs`, фільтри `filters`, пул для Match `matchPool`).
- Поточний вибраний товар (`spProduct`).

**структура глобального стану S:**
- `catalog`: Об'єкт з масивом товарів `all`.
- `cart`: Масив об'єктів товарів.
- `recent`: Масив ID товарів.
- `favs`: Набір/масив ID улюблених товарів.
- `gender`: Рядок/значення статі.
- `tabs`: Стан вкладок.
- `filters`: Об'єкт фільтрів.
- `matchPool`: Пул для системи Match.
- `spProduct`: Поточний об'єкт товару.

**де створюється S:**
У глобальній області видимості у файлі `js/state.js`.

**де змінюється S:**
- `S.cart`: Оновлюється у `js/products.js` через виклик `saveCart()`.
- `S.spProduct`: Оновлюється у `js/products.js` під час вибору товару в гріді.
- `S.recent`: Оновлюється у `js/products.js` через `trackView`.
- `S.favs`: Оновлюється через `quickToggleFav`.

**роль getCatalog:**
Функція обробки динамічної фільтрації каталогу.

**які фільтри застосовуються:**
- Стать (gender).
- Ціна (price).
- Пошук (search).
- Сезонність (seasonality).

**як формується фінальний список товарів:**
Викликається `getCatalog()`, яка фільтрує основний масив `S.catalog.all` за поточними фільтрами та сезонними обмеженнями (напр. приховування зимових товарів влітку).

**які значення читаються з localStorage:**
- `wow_seed` (з sessionStorage).
- Дані кошика (`cart`).
- Дані улюблених (`favs`).
- Вибрана стать (`gender`).

**які значення записуються у localStorage:**
- `wow_seed` (з sessionStorage).
- Дані кошика (`cart`).
- Дані улюблених (`favs`).
- Вибрана стать (`gender`).

**залежності від CFG:**
- `CFG.HOT_SIZES_FEMALE` та `CFG.HOT_SIZES_MALE` для визначення популярних розмірів.
- `CFG.GRID_BATCH` для розміру пачки при рендерингу гріда.

**зв’язки між products.js та state.js:**
`products.js` активно записує дані до `S.cart`, `S.recent` та `S.spProduct`. Використовує `S.catalog` як основне джерело даних для рендерингу всіх компонентів каталогу та головної сторінки.

**функції, які очікують інші модулі:**
- `saveCart()`, `updateBadges()`, `openSizePicker()`, `openProductDetail()`, `changeTab()`, `openBrand()` (ймовірно з `js/ui.js` або `js/app.js`).
- `toast()`, `_haptic()` (утиліти).
- `_isSummer()`, `_isWinter()`, `_brandGrad()`, `_brandGlow()` (допоміжні функції).

**підтверджені технічні ризики:**
- Використання глобального об'єкта `S` створює високу залежність між модулями.
- Детерміністичний shuffle може бути передбачуваним, якщо seed недостатньо складний.
- Інтенсивні операції з DOM у функціях рендерингу головної сторінки (`renderHomeAllGrid`).
