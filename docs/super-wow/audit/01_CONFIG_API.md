# AUDIT: CONFIG & API

Прочитані файли:
js/config.js
js/api.js

Підтверджені факти:
- роль config.js: містить центральну конфігурацію сайту, параметри API та загальні константи.
- роль api.js: відповідає за завантаження каталогу, кеш, нормалізацію товарів, мережеві запити та інтеграцію аналітики.
- поточні джерела каталогу: data/products.json (пріоритетне статичне), data/products_auto.json (резервне), Google Apps Script (fallback).
- роль кешу: localStorage використовується для швидкого кешованого завантаження даних.
- роль GAS: використовується як fallback для каталогу та endpoint для POST-операцій.
- роль products_auto.json: резервне джерело товарів.
- роль extra_photos.json: доповнює фотографії товарів.
- залежності CFG та S: конфігурація впливає на початкові значення в глобальному стані S.

Підтверджені технічні ризики:
- Полегшення завантаження через локальний кеш може призводити до відображення застарілих даних, якщо механізм інвалідації кешу не спрацює.
- Залежність від Google Apps Script як fallback може створювати додаткові затримки мережі.

HYPOTHESIS:
- localStorage теоретично може мати обмеження при великому кеші, але проблема переповнення не підтверджена runtime-тестом.
- точна поведінка S, getCatalog, renderHome і renderCatalog потребує читання інших файлів.
